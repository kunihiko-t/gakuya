# gakuya 最初の版：動画レビュー 設計

- 日付：2026-11-06
- 状態：実装済み。サーバーと CLI はこのあと Go に置き換えた（下の「Go への移行」を参照）

## 何のためか

AITuber の映像の調整では、口で伝えにくいことが多い。たとえば、袖の内側に変な肌色が出ているとき、今は画面を撮って拡大し、「腕のあたり」と言葉で説明している。どのコマの話かも正確には伝わらない。音についても、聞いて「なんか気持ち悪い」と感じるだけで、どこがずれているのか手がかりがない。

gakuya は、最終的に AITuber のステージ（カメラ、色、照明）を人と AI が一緒に調整するアプリになる。最初の版はその入口として、**書き出した動画を止めて拡大し、「このあたりへん」と AI に正確に伝えて、直るまでを見届ける**ところだけを作る。最終的に OSS にするので、主な利用者である AITuber 開発者が、動画ファイルだけで使えるようにする。

## 利用の流れ

ユーザーの言葉と、画面案で「イメージはこんな感じ」と確認した流れは次のとおり。

1. **人が指す：** タイムラインをラフに範囲選択し、絵の上をクリックするか雑に丸で囲み、一言書く。
2. **AI が確かめる：** AI が指摘を読み、「ここですか？」と範囲を画面上に示す。
3. **「はい」で修正に入る：** 人が「はい」を押すと、AI はそのまま修正に入る。「ちがう」なら 1 に戻る。
4. **見比べる：** 書き出し直した動画を、同じコマで前の版と並べて確かめる。指摘は解決か未解決で残る。

## 目標

### 動画を開く
- `gakuya <動画ファイル>`（ふだんは AI エージェントが起動する） で、手元のサーバーが起動してブラウザが開く。
- アカウントも外部サービスも要らない。動画はどこにも送らない。

### コマ単位で見る
- 再生、一時停止、`←` `→` で 1 コマ移動、ホイールで拡大、ドラッグで移動。
- 現在のコマ番号を常に表示する（0 始まり）。
- 表示しているコマと、表示している番号は必ず一致する。番号を焼き込んだテスト動画で全コマを確かめる。

### タイムライン
- 音の波形、拍の線、動きの強さのグラフ、指摘の印を重ねて出す。
- ドラッグでラフに範囲を選べる。正確な範囲は AI が 2 の段階で詰める。

### 指摘を残す
- 範囲、絵の上の位置（クリックまたは雑な囲み）、一言の文章を残す。
- 座標はズームに関係なく、動画に対する 0〜1 で保存する。
- 「この色にしたい」と色を添えられる。ブラウザ標準のカラーピッカーと、絵の上から色を取るスポイトを使う。この版では、色を選んでも絵は変わらない。
- 保存と同時に、範囲の先頭、中央、末尾のコマを PNG で書き出す。印ありと印なしの両方を作る。AI は図形の座標より画像のほうが確実に場所を読める。

### AI が読み書きする
- 指摘は JSON と PNG のファイルなので、AI は読むだけで済む。
- シェルを使える AI エージェントなら、次の CLI で流れに参加できる。特定のエージェントに依存しない。

```bash
gakuya wait                     # 次の出来事（新しい指摘、「はい」、「ちがう」、「まだ」）が来るまで待ち、JSON を標準出力に出す
gakuya propose <id> --frames 1218-1252 --region '<多角形の JSON>' --text "ここですか？…"
gakuya done <id> --video <書き出し直した動画>
```

- **Claude Code のセッションに直接届ける（ユーザーの要望）：** セッションが `gakuya wait` を裏で実行しておくと、指摘や「はい」が届いた時点でコマンドが終わり、その結果でセッションの続きが動く。人はアプリで指すだけで、ターミナルに貼り付けなくてよい。この手順を書いた Claude Code 用のスキルを同梱し、出来事を処理したら次の `wait` を始めるようにする。他のエージェントも同じ CLI を使う。
- `propose` が届くと、画面に青い範囲と「はい」「ちがう」が出る。
- AI が `wait` していないときは、画面に「AI は待機していません」と出す。指摘は失われず、次の `wait` で渡す。
- `done` が届くと、新しい動画を読み込み、同じコマを前の版と並べる。人が「直った」か「まだ」を押す。

### 音との合わせ
- 読み込んだ動画の音から、BPM と拍の位置を自動で求める。
- 映像のコマどうしの差から、動きの強さと動きの起点を求める。カットの切り替わりは動きとして数えない。
- 再生中、絵の外のふちを軽く光らせる。拍と動きの起点は別の色にして、二つのズレが見えるようにする。切り替えられる。絵には重ねない。
- 自動解析は外れることがあるので、BPM と開始位置は人が画面で直せる。AI は `gakuya timing` で直せる。
- 「本来の動きの起点」を、AI や人が時刻の一覧として書けるようにする。モーションデータを読める AI なら、より正確な起点を渡せる。

### 左右に並べて比べる
- 右に並べられるのは、前の版と、手元のファイルから指定した見本の動画である。操作は同じにする。
- 再生、一時停止、コマ送りは左右が一緒に動く。片方を止めれば、もう片方も同じタイミングで止まる。拡大と移動も左右でそろえる。
- 見本は開始位置のズレを人が合わせられる。ズレを合わせたあとは、その位置関係を保って動く。
- 見本は読み込むだけで、コピーも保存もしない。パスだけを覚える。

## 目標にしないこと

後の版で扱うか、必要になるまで作らない。

- three.js のステージ、照明や色のリアルタイム調整。**ユーザーは本物の照明と反射光がその場で変わることを望んでいる。** 次の版の本題であり、動画の上で色を変える見本にはしないと確認済み。
- Unity の 1 コマ撮影、LUT、破綻の自動検出、ショット表の帯。
- 色の補正そのもの。この版では「この色にしたい」と伝えるだけ。
- MCP サーバー。CLI の薄い包みとして後から足せる。
- 共有、アカウント、同時編集、承認の流れ。
- YouTube の URL の読み込み。コマ単位で合わせられない。
- VMD や VRMA の読み込み。動画だけで動かす。
- 公開の作業とライセンスの決定。**ライセンスはユーザーの判断待ちで、それまで入れない。**

## 失敗とみなすこと

動いていても、次の場合は失敗である。

- 表示と番号が 1 コマでもずれる。AI が別のコマを直すことになる。
- 書き出し直した動画に、古い指摘を黙って当てる。動画のハッシュが違うときは、版が違うことを必ず画面に出す。
- 人が「はい」を押す前に、AI が修正に入る。
- エンジンや特定のモデルがないと使えない。
- ラフに指せない。ピクセル単位の操作を求めるなら、この道具を作る意味がない。

## 守ること

- 個人のモデル、モーション、秘密情報、決め打ちのパスをリポジトリに入れない。テストの動画は、その場で生成するか、利用者の手元のものを使う。
- サーバーは `127.0.0.1` でだけ待ち受ける。`Host` と `Origin` を確かめ、起動ごとのトークンを要求する。CLI はトークンを保存先のファイルから読む。
- AGPL、GPL のコードを入れない。依存は MIT、Apache、BSD、MPL に限る。
- 調査で挙げたツールはどれも動かしていない。頼る前に動かして確かめる。
- コミットとプッシュはユーザーが頼んだときだけ。
- 配信中の OBS、ライブの stage、Unity のシーンに触らない。

## 保存するもの

既定では、起動した場所の `.gakuya/<レビュー名>/` に置く。レビュー名は既定で動画のファイル名（拡張子なし）とし、`--review` で変えられる。別の名前で書き出し直しても `gakuya done` で同じレビューの新しい版になる。別の動画を開くと別のレビューになる。起動時の動画と同じハッシュの版を持つレビューがあれば、それを開く。

前の版と見比べるために、版を登録するときに動画を `.gakuya/<レビュー名>/versions/` へコピーする。同じパスへの上書きや移動があっても比べられる。その分ディスクを使うので、`.gakuya/` は git に入れない前提とし、README に書く。見本はコピーしない。見本のファイルが見つからないときは、その旨を画面に出す。

```json
{
  "versions": [
    { "id": "v1", "path": "dance.mp4", "sha256": "…", "fps": 30, "frames": 1146, "width": 1080, "height": 1920 }
  ],
  "reference": { "path": "reference.mp4", "offsetSeconds": -0.4 },
  "timing": { "bpm": 128, "offset": 0.18, "source": "auto", "cues": [] },
  "notes": [
    {
      "id": "n1",
      "version": "v1",
      "status": "open",
      "frames": [1218, 1252],
      "anchor": { "frame": 1234, "shape": [[0.41, 0.62], [0.55, 0.60]] },
      "text": "腕のところに変な肌色が出てる",
      "color": null,
      "snapshots": ["notes/n1-1218.png", "notes/n1-1234.png", "notes/n1-1252.png"],
      "proposal": null
    }
  ]
}
```

指摘の状態は `open`（AI に渡す前）、`proposed`（「ここですか？」）、`confirmed`（「はい」）、`fixed`（見比べ待ち）、`resolved`（直った）と進む。「ちがう」は `open` に、「まだ」は `confirmed` に戻す。動きの解析の結果は再計算できるので、別のキャッシュファイルに置く。

上の JSON は形の例で、項目の細部は実装で決めてよい。

## 細かい決定（設計者の判断）

ユーザーとは話していない点で、設計者が決めた。

- **コマ番号の一致の範囲：** 一致を保証するのは一時停止中である。再生中の番号は目安とし、止めた瞬間に正確なコマと番号へ置き換える。完了条件 1 も一時停止中のコマで確かめる。
- **左右のそろえ方：** 左を基準にする。右には、左の時刻（見本はズレの秒数を足した時刻）を含むコマを出す。fps や長さが違っても時刻でそろえる。fps が同じ版どうしでは、これは同じ番号のコマになる。右に対応するコマがないときは、その旨を出す。
- **複数の指摘を一度に直すとき：** `done` は指摘ごとに呼ぶ。同じハッシュの動画は一つの版にまとめる。
- **版をまたぐ指摘：** `done` された指摘と「まだ」の指摘は新しい版へ移る。他の指摘は元の版のまま残し、「前の版の指摘」と印を付ける。古い指摘を新しい絵に黙って当てない。
- **「ちがう」と「まだ」の理由：** どちらも任意で一言添えられ、`wait` が AI に渡す。「ちがう」のときは、人は同じ指摘の印と範囲を直せる。AI はそれを受けて `propose` し直す。
- **拍と起点の直し方：** `gakuya timing --bpm <値> --offset <秒> --cues <ファイル>` を足し、AI もサーバー経由で書く。レビューの JSON を AI が直接書くことはしない。
- **起点の光り方：** ふちの光の一色は基準で、`cues` があれば `cues`、なければ拍である。もう一色は映像から求めた実際の動きである。タイムラインには三つとも出す。`timing` は版をまたいで引き継ぐ。
- **動画の中の移動（ユーザーの追加指示）：** 再生と停止はいつでもできる。シークバーのつまみをスライドすると絵がついてくる。再生中にスライドや帯のクリックをしたら、そこから再生を続ける。帯のドラッグは範囲選択のまま。
- **視点（ユーザーの追加指示）：** 再生中でも停止中でも絵を拡大・移動できる。動画は1台のカメラの絵なので、この版の「視点変更」は絵の拡大と移動である。再生中に絵を指すと、その正確なコマで止まり、視点はそのまま残る。

## 作り方

- **サーバー：** 依存はできるだけ足さない。値の変更は HTTP、画面への通知は Server-Sent Events で足りる。ファイルに書くのはサーバーだけにして、書き込みは一時ファイルからの置き換えで行う。CLI もサーバー経由で書く。
- **画面：** フレームワークなしの TypeScript。この版に three.js は要らない。
- **コマの取得：** 一時停止中のコマは mediabunny（MPL-2.0）で動画の時刻から正確に取る。再生と音は `<video>` に任せる。動かして確かめ、実際の書き出しで全コマ一致しなければ別の方法にする。
- **対応ブラウザ：** まず Chrome。WebCodecs に依存するので、Safari で動くかは確認して README に書く。

## 作る人に任せること

- 拍の検出を自作にするか、ライブラリにするか。条件は依存の制限を守ること、クリック音の入った合成音で位置が正しいことを確かめること。
- 動きの起点の求め方。縮小したコマの差で始めてよい。
- 画面の細部。ただし画面案の配置（中央に絵、右に指摘と AI、下にタイムライン）を保つ。

## 動いたと言える条件

1. 番号を焼き込んだテスト動画（30fps と 60fps、ffmpeg でその場で生成）で、全コマの表示と番号が一致する。
2. このセッションの Claude Code を AI 役にして、実際のダンス動画（手元のもの、リポジトリには入れない）で、利用の流れの 1〜4 を最初から最後まで通せる。
3. クリック音の合成音で、ふちの光る位置が音と合う。
4. 前の版と見本の動画のそれぞれを左右に並べて、再生、一時停止、コマ送りが一緒に動き、止めた位置がそろう。
5. リポジトリに個人の素材と決め打ちのパスがない。

## Go への移行

実装のあと、サーバーと CLI を Go（標準ライブラリのみ）に置き換え、画面を埋め込んだ単一の実行ファイルにした。
Node が要るのはビルドのときだけになり、実行に要るのは Chrome だけになった。
画面は TypeScript と mediabunny のままで、review.json の形も変えていない。
